# Architecture Change Protocol

The architecture lock is frozen. An implementation PR must not modify it as a shortcut.

A proposed architecture change must contain:

1. rationale and problem statement
2. affected frozen invariants
3. alternatives considered
4. migration/compatibility impact
5. security/privacy impact
6. updated requirements
7. updated work items and dependency graph
8. updated implementation contracts
9. new immutable architecture-lock version
10. explicit approval before implementation

Until approved and recorded, existing repository architecture remains authoritative.
